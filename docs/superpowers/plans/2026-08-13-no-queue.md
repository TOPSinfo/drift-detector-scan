# No Queue Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A scan resolves every host in one run. `queued` stops existing as something a user sees, without a single AI record entering the certified payload.

**Architecture:** The AI never writes the answer. It writes *evidence*; a gate refuses anything unevidenced; the evidence lands in the local reviewed-data overlay; and the **deterministic scanner re-derives the answer on a second zero-token pass**. `drift.json` is produced entirely by that second pass, so `check_ai_firewall` is untouched. This is the existing `absorb` doctrine applied to coverage.

**Tech Stack:** Python 3.11+ (stdlib + PyYAML), pytest, YAML overlays under `$DRIFT_CATALOG_DIR`.

## Global Constraints

- **Runtime deps stdlib + PyYAML only.** Deterministic; `now` passed in; no wall-clock in logic.
- **The certified payload stays deterministic.** `drift.json` comes from the deterministic scan only. `verify.check_ai_firewall` must keep passing unchanged.
- **The date gate does not move.** A retirement date requires a source URL fetched that session with the date appearing **verbatim** in the excerpt (`agent/absorb.py:date_in_text`). Identity and ownership the AI may settle; dates it may only propose.
- **A catalogued vendor may NEVER be claimed as own-infra**, whatever the token or the AI says. The existing deterministic guard in `own_infra` stays and the AI cannot override it. This is the `acme-mailgun-sync` bug; it is what replaces the hedge being removed.
- **Client hostnames never enter the public tree.** Own-domain entries go in the local overlay (`$DRIFT_CATALOG_DIR`, default `~/.drift/catalog`), never `agent/*.yaml`.
- **A failed AI pass degrades, never blocks.** No model, no network → the run still completes, hosts land in `needs human`, and the report says so. The deterministic report is never withheld.
- **"Cannot see" ≠ "clean".** Removing `queued` makes an empty tree assert *resolved*. That is only honest if the pass ran — so an unrun pass must be visible, not silent.
- Every guard proven against its bug — shown to FAIL first.
- **Test command:** `.venv/bin/python -m pytest -q`. Baseline: **1084 passed, 3 skipped**.

### Task 2: the resolution gate

**Files:** Create `agent/resolve.py`; modify `agent/cli.py`; test `tests/test_resolve_gate.py`.

**Interfaces:** `drift-scan resolve --state <dir>` prints the unresolved work-list as JSON (what the AI consumes). `drift-scan resolve --state <dir> --apply <verdicts.json> --now <date>` gate-validates and writes the overlay entries. Exit 3 = gate rejected; exit 0 = applied.

**The gate — refuse, do not sanitise:**
- an `own-domain` verdict needs a non-empty `reason`, and its domain must not match a catalogued vendor;
- a `vendor-identity` verdict needs a `source_url` fetched this session confirming the host belongs to that vendor;
- a `retiring` verdict needs `source_url` + `date` + `excerpt`, with the date **verbatim** in the excerpt — reuse `agent.absorb.date_in_text`, do not reimplement it;
- an `unknown` verdict is legitimate and lands the host in `needs-human`.

- [ ] **Step 1: failing tests**, one per refusal: an own-domain with no reason; an own-domain naming a catalogued vendor; a vendor-identity with no source; a `retiring` whose date is absent from its excerpt (the exact bug that motivated this project's date gate); and a well-formed set that applies cleanly.
- [ ] **Step 2:** run, watch them fail. **Step 3:** implement. **Step 4:** pass + full suite. **Step 5:** commit.
